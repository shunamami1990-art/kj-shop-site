- 项目：shop-site
- 依据：契约 v0.16.1（`contracts/MANIFEST.json`；0.15.3 → 0.16.1 对站点接口 C1 无改动）。先按开发规范第 7 节核对 `docs/design.md` 的"依据"。
- 批次：batch-384
- 上限：最多 70 轮。依据：sonnet；加一列、改一处写入、一处显示和测试，同类 T-003（26 轮）、T-002（90 轮，较大）
- 风险：低；审查：架构师核对 diff

## 背景

2026-11-15 负责人在示例站试下单：平台返回 `PAY_METHOD_UNAVAILABLE`（店铺码不足），买家在下单页看到了提示，但之后打开"我的订单"的订单页只显示"订单尚未提交到平台"，看不出是被平台拒绝、拒绝的原因是什么，排查要去平台后台。

## 要做的

1. `lib/db.js` 的 `orders` 表加两列 `last_error_code TEXT`、`last_error_text TEXT`（`ALTER TABLE ... ADD COLUMN` 按现有"IF NOT EXISTS / 启动时补列"的做法，已有数据库升级后能用）。
2. `lib/orders.js` 提交订单到平台被**明确拒绝**（`businessErrorStatus` 这一支，不是结果未知那一支）时，把平台的错误码和 `errorText` 的说明写到这两列；再次提交成功时清空。结果未知、签名错误（`KjSignatureError`）不写（保持现有处理）。
3. 订单页 `app/orders/[no]/page.jsx`：没有平台订单号且有 `last_error_code` 时，把"订单尚未提交到平台。"改为"平台拒绝了这笔订单：<说明>（错误码 <code>）"；买家能再次下单的话给"重新下单"的链接（已有的话不重复加）。
4. 测试（`test/`）：拒绝后订单页显示错误码和说明；结果未知不写；再次成功后清空。
5. `docs/design.md` 订单一节补这两列和显示规则，"依据"升到 0.16.1。
6. `CLAUDE.md` 第 8 节的表加一行：`| 原地修改本文件夹里的文件 | `sed -i ... <本文件夹内的文件>`（路径检查核对；宿主机上执行代码的 python3 等仍不放行） |`（权限已放行，B-91）。

## 不做

- 不改下单页的提示；不自动重试提交；不把平台的原始 `message` 不经 `errorText` 直接显示。

## 验收

- `sh .githooks/run-verify.sh`：`KJ-STATUS: passed`（含用词检查）。
- 结果里写：改动文件、新测试名、显示文字原样。

## 结果

状态：完成。`sh .githooks/run-verify.sh`：`KJ-STATUS: passed`。

改动文件：
- `lib/db.js`：`orders` 加 `last_error_code`、`last_error_text`（新库建表带列；旧库启动时按 `PRAGMA table_info` 检查后 `ALTER TABLE ADD COLUMN`）；新增 `setLastError`。
- `lib/orders.js`：`submitOrder` 明确拒绝时写错误码和 `errorText` 的说明，提交成功时清空；结果未知、回复验签失败不写；新增 `notSubmittedText`。
- `app/orders/[no]/page.jsx`：没有平台订单号且有 `last_error_code` 时显示拒绝说明，订单有商品时附"重新下单"链接（`/buy/<商品编号>`，此前订单页没有该链接）。
- `test/order-rejection.test.mjs`（新）、`docs/design.md`（依据升到 0.16.1，订单一节和测试清单）、`docs/database.md`（两列）、`CLAUDE.md` 第 8 节（加 `sed -i` 一行）。

新测试（4 个，全部通过）：
- 平台明确拒绝：记错误码和说明，订单页显示拒绝原因
- 结果未知不写错误码，订单页仍显示尚未提交
- 再次提交成功后清空错误码和说明
- 旧版 orders 表启动时补上两列，重复启动不报错

显示文字原样：`平台拒绝了这笔订单：<说明>（错误码 <code>）`，例如 `平台拒绝了这笔订单：该支付方式当前不可用，请换一种支付方式（错误码 PAY_METHOD_UNAVAILABLE）`；后接链接"重新下单"。没有错误码时仍是 `订单尚未提交到平台。`。

说明：
- 订单页是 JSX，现有测试框架不渲染页面，所以显示文字放在 `lib/orders.js` 的 `notSubmittedText`，测试覆盖该函数；页面只调用它，页面本身没有渲染测试。
- 明确拒绝时订单同时置 `closed`（现有行为），`/api/pay/retry` 对 closed 订单回 409，所以"再次成功清空"只发生在 created 的订单上，测试用 `setLastError` 构造该状态。
- 过程中一条用 sed 带花括号写法的命令被拦截，改用 Edit 工具完成，未重试。
